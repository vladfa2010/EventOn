# Архитектура проекта

## Общая схема

```
Браузер                          server.js (Node 20)              Внешние сервисы
┌──────────────────┐            ┌─────────────────────┐          ┌──────────────────┐
│ index.html       │  статика   │ статик-сервер       │          │ api.moonshot.ai  │
│ ├ глобус (3D)    │◄───────────│ (ручная раздача     │          │ /v1 (Kimi k2.6   │
│ ├ карусели       │            │  файлов, без deps)  │          │  + $web_search)  │
│ ├ гео-консент    │  poll 10с  │                     │  HTTPS   └──────────────────┘
│ └ пилюля локации │───────────►│ GET /api/around     │─────────►┌──────────────────┐
│                  │            │  (фоновая задача)   │          │ Nominatim        │
│                  │  геокодинг │ GET /api/geocode    │─────────►│ (OSM, primary)   │
│                  │───────────►│                     │          │ Photon (fallback)│
│                  │  email     │ POST /api/subscribe │          └──────────────────┘
│                  │───────────►│  → subscribers.csv  │
└──────────────────┘            └─────────────────────┘
```

## Файлы

### `app/index.html` (~1,2 МБ) — весь фронтенд

Единственный файл страницы: разметка, весь CSS (~400 строк), весь JS (~120 КБ кода) + встроенная base64-текстура ночной Земли (~1 МБ, `EARTH_NIGHT_B64`). Three.js r152.2 подключается с CDN.

Ключевые блоки внутри:

| Блок | Строки (примерно) | Назначение |
|---|---|---|
| `:root` + CSS | 10–440 | Дизайн-система: цвета, карточки, пилюли, оверлей, гео-карточка |
| Разметка секций | 390–560 | hero + глобус, фильтры, «Вокруг вас», Right Now, Online, оверлей, футер |
| `EVENTS` | 555–595 | Статическая база событий (35 шт., поля: id, title, tag, chip, city, badge, date, lat/lng, color, desc, link, source) |
| Карусели | 596–680 | Партии загрузки, палитра, рендер лент, чипы-фильтры, оверлей |
| Глобус | 720–955 | Three.js: текстура с фолбэком, маркеры, user-маркер, drag/zoom, raycast-тултипы, защита pointer capture |
| Гео-консент + «Вокруг вас» | 956–1190 | Карточка разрешения гео, ручной ввод города, пилюля локации, fillAround, карточка почты |
| Форма добавления события | 1193+ | FAB «+» → модалка, добавление в EVENTS |

### `app/server.js` (18 КБ) — бэкенд без зависимостей

Чистый `node:http`. Четыре зоны:

1. **Конфиг**: ручной парсер `.env` (без dotenv), константы `MODELS`, `CACHE_TTL=12ч`.
2. **Kimi API** (`chat`, `askKimi`) — см. [ллм-блок.md](ллм-блок.md).
3. **Геокодинг** (`nomFetch`, `photonFetch`, `reverseCity`, `forwardCity`) — Nominatim с circuit-breaker'ом (10 мин после сбоя), Photon с 3 ретраями и бэкоффом 2,5с; приоритет типов `city > town > village > municipality > district > county > state`, срезание префикса «городской округ».
4. **HTTP-маршруты**:

| Маршрут | Ответ |
|---|---|
| `GET /api/geocode?lat&lng` | `{ok, city}` — обратный геокодинг (кэш по округлённым координатам) |
| `GET /api/geocode?city=…` | `{ok, city, lat, lng}` — прямой геокодинг |
| `GET /api/around?lat&lng&city` | мгновенно `{ok, pending, city}` → фоновая задача; повторные вызовы → `{ok, city, events[], cached}` |
| `POST /api/subscribe` | `{email, city}` → строка в `subscribers.csv` (ISO;email;city) |
| `/.env`, `/subscribers.csv`, `/.`* | 404 — секреты недоступны извне |
| прочее | статика (`/` → `index.html`) |

**Важно**: город в `/api/around` авторитетно определяется сервером по координатам (геокодер), параметр `city` от клиента — только фолбэк. Это убирает ошибки клиентского хардкод-списка («вместо Екатеринбурга — Москва»).

### `app/package.json`

Минимальный манифест: `"start": "node server.js"`, Node ≥ 20. Зависимостей нет.

### `app/Dockerfile`

```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY . .
ENV PORT=3000
EXPOSE 3000
CMD ["npm", "start"]
```

Render собирает образ из репозитория и подставляет свой `PORT`.

### `.gitignore`

```
.env
node_modules/
subscribers.csv
```

`subscribers.csv` живёт только на диске инстанса (на Render — эфемерная ФС, при передеплое файл обнуляется; на текущем этапе «просто собираем адреса» — приемлемо).

### Секреты (вне репозитория)

- `MOONSHOT_API_KEY`, `MOONSHOT_BASE_URL=https://api.moonshot.ai/v1` — локально в `/mnt/agents/secrets/planeta-on.env`, на Render — в env-переменных сервиса. Ключ нигде не попадает в клиентский код и GitHub.
- GitHub PAT для пушей — отдельно, в команды подставляется с маскировкой в логах.

## Потоки данных

### Режим статики (без сервера)

`index.html` открывается напрямую (file:// или любой статик-хостинг). Всё работает, кроме `/api/*`: гео-ручной ввод падает в локальный словарь `geoFromCity`, «Вокруг вас» показывает только ближайшие события из базы, подписка складывается в `localStorage.subQueue`.

### Полный режим (Render)

1. Пользователь даёт гео → клиент сразу рисует «Вокруг вас» из базы (≤500 км) и просит `/api/geocode` уточнить город.
2. Параллельно стартует `/api/around` — сервер запускает фоновую задачу поиска Kimi, клиент опрашивает каждые 10 с.
3. Готовый список событий полностью перерисовывает карусель «Вокруг вас»; результат кэшируется на 12 ч (пустой — на 5 мин).
4. Почта из карточки подписки уходит в `subscribers.csv`.
